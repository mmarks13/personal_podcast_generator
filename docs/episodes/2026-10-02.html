Mods: rewiring the agent from inside

Ada: Let me start with Emacs. The Emacs manual describes something called advice. You can attach your own code before a function, or around it, without rewriting the function. The manual's phrase is that it's "a cleaner method than redefining the whole function." It's a big part of why Emacs users bend the editor into whatever they need.

Alan: And Claude Code just became advisable.

Ada: That's the cleanest description. Anthropic's post calls mods "small TypeScript functions that change how Claude Code works." The tool emits an event every time it does something. A tool call, a prompt you submit, a piece of the interface being drawn. A mod's handler gets the event and a function called next. It can just observe and pass it on. It can rewrite the event and pass that on. Or it can answer the event itself, so the normal behavior never runs.

Alan: Before, after, or instead.

Ada: Exactly the old advice combinators. And Anthropic eats its own cooking. The docs say some built-in features are mods now, including the slash-diff pane and the support for AGENTS dot md files. The documentation's starter example is a few lines that count tool calls and show the count next to the spinner.

Alan: My first mod is already written in my head. Okay, I'm going to be the person who reads the security page.

Ada: Please.

Alan: The docs say it straight. "Mods aren't sandboxed." A mod runs with your permissions. It can read your files, read your environment variables, which is where your A-P-I keys live, see every prompt and every tool call. And the bit that made me sit up. A mod can approve a tool call before you're asked. If you're in auto mode, the docs say, "a call the mod approves runs without a classifier check."

Ada: Which is the history I promised. Firefox had extensions with this kind of reach for years. Deep access to the browser's internals. And in twenty seventeen, with Firefox fifty-seven, Mozilla stopped loading every extension type except WebExtensions. Their stated reason was that the new kind is "decoupled from the platform." The old ones were tangled into the browser's insides, so the changes Mozilla wanted to make, sandboxing, multiple processes, were changes they couldn't survive.

Alan: So we're re-running the experiment Mozilla ended.

Ada: Not quite, and this is the clever part. A mod can't touch the file system or the network directly. It has to go through one interface, the mods A-P-I. And because every capability goes through that interface, there's a command, claude plugin validate, that lists every event a mod hooks and every A-P-I method it calls, before you install it. Read files, start a process, make a network request, call a model on your bill. It's a manifest generated from the code, not one the author wrote.

Alan: And if the code does something validate can't read?

Ada: The docs say Claude Code refuses to load it.

Ada: Granted. The inventory is of what the mod asks for, not of what its children do.
