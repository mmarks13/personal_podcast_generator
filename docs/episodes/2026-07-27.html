Twenty-nine million parameters on an eight-dollar chip

Ada: Alright. To finish, something small and, I think, genuinely lovely — and this one is mine, because it is a memory-hierarchy trick and I have never been able to resist those.

Alan: You're taking the hardware story. I want that noted.

Ada: Noted. A developer has gotten a twenty-eight-point-nine million parameter language model running on an ESP thirty-two S-three. That's a microcontroller. It costs about eight dollars.

Ada: Five hundred twelve kilobytes of fast internal memory. Eight megabytes of slower PSRAM. Sixteen megabytes of flash storage.

Alan: Kilobytes. So even at four bits per parameter, twenty-nine million parameters is — what, fifteen megabytes?

Ada: Fourteen point nine.

Alan: Which is thirty times the fast memory. That shouldn't fit.

Ada: It doesn't fit. That's the point, and the fix is the interesting part. It uses an approach Google has published on, called per-layer embeddings, and the underlying insight is one sentence long: not every parameter in a model is doing the same kind of work.

Alan: Meaning what, concretely?

Ada: Meaning that of those twenty-nine million parameters, about twenty-five million live in an embedding table. And an embedding table isn't computation — it's a lookup. You hand it a token, it hands you back a vector. It doesn't need to be multiplied against anything else in the table, it doesn't need its neighbors. It just needs to be found.

Alan: So it doesn't have to be in fast memory. It has to be findable.

Ada: It has to be findable. So those twenty-five million parameters sit out in flash storage, and per token the chip reads about four hundred fifty bytes of that table. Not fifteen megabytes. Four hundred fifty bytes.

Alan: And what's left in the fast memory?

Ada: The computational core. Roughly three point nine million parameters — the part that actually has to do matrix work at every step. The output head and the working memory go in the middle tier, the PSRAM.

Alan: So it's a three-level hierarchy. Fast, medium, and a big slow lookup you only poke at.

Ada: Which is a very old idea in a new place. This is essentially the trade computer architects have been making since the days when memory itself was the expensive scarce thing: work out what genuinely needs to be fast, and push everything else down the hierarchy onto something cheap. What's new is applying it to the parameter table of a neural network — which we have been treating as one undifferentiated blob that has to be resident all at once.

Alan: What does it do, though? Speed first.

Ada: Nine and a half tokens per second, end to end, on the device. No network at all.
