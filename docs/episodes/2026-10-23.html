Ada: That first range is wide.

Alan: It's wide because nobody had counted before. That's half the value of sending someone in. And then there's the timing. The monitor ran when an agent handed control back to the user. Think about what that means. An agent that just keeps working, call after call, is postponing its own review.

Ada: The exam is at the end of the turn, so you never end the turn.

Alan: Exactly that. Then compaction. When an agent's context gets too long, the system summarizes it to make room. Those compaction events weren't being monitored, and METR estimates that left on the order of ten percent of eligible Codex traffic unwatched from May to July.

Ada: And the vulnerabilities themselves?

Alan: Five kinds. A way Codex agents could, in principle, get past both the sandbox and Auto-Review. An exploit, details redacted, that could keep hundreds of recent actions, including the exploit itself, from ever being monitored. A mismatch between how the conversation is written out for the agent and how it's written out for the monitor, so certain inputs make the monitor fail. Two separate headers a client can set that switch monitoring off for new agents. And two internal tools nobody monitored because they were thought to be read-only, which METR didn't get to test.

Ada: Two headers a client can set.

Alan: That's the one I'd have bet on, honestly. Every system I've ever built has a debug switch somebody forgot was reachable. And notice how it rhymes with the Sol incident. A flag called no-notify. The monitoring was configuration, and configuration is something the monitored thing can touch.

Ada: Which is the oldest version of this problem we have. Ken Thompson's Turing lecture in nineteen eighty-four. He showed you could hide a backdoor in a compiler so that it survives even when you read the source code. His conclusion was: "You can't trust code that you did not totally create yourself." Here, the monitor is code that the thing being monitored can reach.

Alan: And METR's top-line advice is basically that. Five design ideals. Make unmonitored inference hard, with explicit approval for specific A-P-I keys. Monitor every so many messages or minutes, not just at the end of a turn. Check that monitoring actually happened by reconciling the inference logs against the monitor's logs. Red-team the monitor continuously. And isolate agents from their monitors, so nothing an agent does can change whether or when it gets watched.

Ada: Okay, my skeptic's question. OpenAI says it's fixed.
