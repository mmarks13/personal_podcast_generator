A language that makes you prove it before it compiles

Ada: Alan sent me a link at eleven at night with no message attached, which is how he asks me to look at something.

Alan: It works.

Ada: It does. Bend. It went up on Hacker News yesterday, five hundred and ninety-one points, three hundred comments, and the tagline on the site is: a fast language that blocks AI mistakes via proof. The subtitle is four things stapled together — C speed, CUDA parallelism, Lean proofs, Python syntax.

Alan: Which is four different research programmes and a marketing department.

Ada: It is. Let me do the idea, and then you can be unpleasant about it. The mechanism has a name and a filename. You write a file called LAWS dot bend, and in it you state invariants about your program. Their examples: the sum of all balances must be zero. Winning is impossible.

Alan: Invariants. Fine, people write those as tests.

Ada: Not as tests. As theorems. Bend's type system is an affine dependent type theory, which means the type checker is also a proof checker — the same family as Lean and Rocq, which are the systems mathematicians use to machine-check proofs. So when your code changes, the compiler demands a proof that the laws still hold. Their sentence: merging a bug is mathematically impossible — it is a theorem.

Alan: And the AI part is just that the thing writing the code is a model.

Ada: That's exactly the AI part, and I think it's the right small idea. The site's example is an agent producing a bug, the compiler refusing it, and the agent retrying until it produces something that proves out. The claim is: no AI can ship one line that breaks them, ever.

Alan: Okay. I've got three.

Ada: Go.

Alan: One. Writing the law is writing a specification, and the specification is where the bugs are. "The sum of all balances must be zero" is a lovely invariant for a ledger and it does not tell you whether you charged the right account. I can satisfy every law in the file and ship something catastrophically wrong.

Ada: That's correct and I don't think they'd argue. What it buys you is a small set of things that are now impossible instead of unlikely. That's not nothing — that's the difference between a class of bug and an instance of one.

Alan: Two. Somebody has to write the proofs. In practice, in a dependent type system, proof effort is not proportional to code size, it's proportional to how awkward your invariant is to state. Easy law, easy proof. Real law about a real system, and you're a graduate student for a fortnight.

Ada: Their answer to that is partly speed — they claim Bend type-checks in a second at most, against minutes for comparable proof checkers.
