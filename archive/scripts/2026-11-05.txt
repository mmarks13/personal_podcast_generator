## Nine hundred forty-eight paths to root
B: So. The kernel. I'll be upfront that OpenAI's page wouldn't load for us, so these numbers come through the detailed write-ups at G-B Hackers and DEV, which agree with each other. The run happened in mid-October, against the kernel of a widely used Linux distribution.
A: And the model?
B: Unnamed. They call it an upcoming cyber model. Here's what it did. Five stages. First, scout agents pick what to read. Out of more than forty million lines of kernel, they chose about five thousand targets, roughly seven percent of the code. Specifically, the parts an ordinary user can reach.
A: That's the clever bit, I'd guess. Choosing where to look.
B: It's the cheap bit too. Scouting cost about thirty-four hundred dollars. Then analyst agents read those targets and filed twenty-three hundred candidate bugs in twelve hours.
A: Twenty-three hundred claims. How many were real?
B: That's stage two, and it's the part that makes this different from a model guessing. Every candidate got run. A triage agent built a test case and fired it at a virtual machine, with a kernel instrumented to catch memory errors as they happen. About three quarters reproduced, seventeen hundred and twenty-four. And of the ones that didn't, only about three percent failed because the model's reading was wrong. Mostly they needed privileges the attacker wouldn't have, or a race the agent couldn't win.
A: So the false-alarm rate on reading code is low. Then exploits.
B: Then exploits, against the standard modern protections turned on. Eleven hundred sixty-nine working privilege escalations. Some of those were the same hole reached different ways, so they grouped them by which patch closes them, and that gives you nine hundred forty-eight. Then a candidate patch for each, then a human review before anything was reported.
A: [skeptical] I want to slow down on "working." How do they know an exploit used the bug it claims to?
