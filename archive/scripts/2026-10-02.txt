## Three ways to build a model that only chooses
B: Quick refresher, one line. A decision model doesn't write text. You give it a situation and typed questions, it gives back probabilities over the allowed answers, in one pass. We did the gold rush yesterday. Today I want the anatomy, because the two new ones are built in genuinely different ways.
A: Go.
B: Amazon first. Strands Decider two-B, from the Strands Agents team. The launch post is by Marc Brooker and two colleagues. They took Qwen three point five, two billion parameters, which they call the "torso." Then they removed the language-model head entirely. The part that turns the last hidden state into a next word, gone. In its place, what they call a "pointer head," which scores each option you offered. Trained with a small rank-sixteen LoRA adapter.
A: So it physically can't write you a sentence.
B: Can't. The post says plainly it's not for "coding, chatbots, document summarization." On JevBench, the public decision benchmark, it's third of thirty-three in its size class. Median about a hundred fifteen milliseconds on an RTX three-ninety, about a hundred fifty-three on an M3 MacBook. And Brooker's line to TechCrunch is the use case: "they make a perfect decider for a workflow step."
A: Second way?
B: Cloudflare's Clef. Two models. Clef at twenty-seven billion parameters, post-trained from Qwen three point eight twenty-seven B, and Clef-flash at nine billion. Apache licensed, weights on Hugging Face, and also hosted on Cloudflare's Workers A-I. Their design is a "joint schema head." The backbone does one prefill pass over the situation and all the questions together. Then a small transformer reads the final hidden states and scores every option of every question jointly.
A: Jointly meaning the questions can see each other.

## Mods: rewiring the agent from inside
A: Let me start with Emacs. The Emacs manual describes something called advice. You can attach your own code before a function, or around it, without rewriting the function. The manual's phrase is that it's "a cleaner method than redefining the whole function." It's a big part of why Emacs users bend the editor into whatever they need.
B: And Claude Code just became advisable.
A: That's the cleanest description. Anthropic's post calls mods "small TypeScript functions that change how Claude Code works." The tool emits an event every time it does something. A tool call, a prompt you submit, a piece of the interface being drawn. A mod's handler gets the event and a function called next. It can just observe and pass it on. It can rewrite the event and pass that on. Or it can answer the event itself, so the normal behavior never runs.
B: Before, after, or instead.
A: Exactly the old advice combinators. And Anthropic eats its own cooking. The docs say some built-in features are mods now, including the slash-diff pane and the support for AGENTS dot md files. The documentation's starter example is a few lines that count tool calls and show the count next to the spinner.
B: [chuckles] My first mod is already written in my head. Okay, I'm going to be the person who reads the security page.
A: Please.
B: The docs say it straight. "Mods aren't sandboxed." A mod runs with your permissions. It can read your files, read your environment variables, which is where your A-P-I keys live, see every prompt and every tool call. And the bit that made me sit up. A mod can approve a tool call before you're asked. If you're in auto mode, the docs say, "a call the mod approves runs without a classifier check."
A: Which is the history I promised. Firefox had extensions with this kind of reach for years. Deep access to the browser's internals. And in twenty seventeen, with Firefox fifty-seven, Mozilla stopped loading every extension type except WebExtensions. Their stated reason was that the new kind is "decoupled from the platform." The old ones were tangled into the browser's insides, so the changes Mozilla wanted to make, sandboxing, multiple processes, were changes they couldn't survive.
B: So we're re-running the experiment Mozilla ended.
A: Not quite, and this is the clever part. A mod can't touch the file system or the network directly. It has to go through one interface, the mods A-P-I. And because every capability goes through that interface, there's a command, claude plugin validate, that lists every event a mod hooks and every A-P-I method it calls, before you install it. Read files, start a process, make a network request, call a model on your bill. It's a manifest generated from the code, not one the author wrote.
B: And if the code does something validate can't read?
A: The docs say Claude Code refuses to load it.
B: Okay, that's good. Here's my problem. One of the methods on that list is "start a process." Once a mod starts a program, that program reaches the network on your account and isn't covered by the session's network policy. The docs say so. So the manifest tells me the mod can launch something. It doesn't tell me what the something does.
A: Granted. The inventory is of what the mod asks for, not of what its children do.
B: And for companies?
A: That's the other half. On Team and Enterprise plans, or any machine with managed settings, a built-in guard called sec-default loads first. It keeps a user's mods from overriding deny rules, from changing what the organization's managed hooks see, and from editing the system prompt or the managed instructions. Admins can allow only their own mods. And they can put a policy mod first in line, which sees every other mod's manifest as it loads and can refuse it.
B: So the audit layer is a mod too.
A: A mod that loads first.
B: [sighs] That's the part I don't love. You know I run a logging proxy in front of anything agentic. The whole point is that it sits outside the thing it's watching. A policy mod sits inside the process it's policing, and the docs say if the mod worker crashes three times, every non-built-in mod unloads, the policy one included, until you reload.
A: That's where the analogy to Emacs breaks, honestly. Emacs advice was one person customizing their own editor. This is an agent with your credentials, plus code from a marketplace, plus the agent itself can write you a mod and hot-reload it mid-session.
B: Which the post advertises. "You can also use Claude Code to mod Claude Code."
A: And settings hooks, the shell-script kind, aren't going anywhere. The admin docs say "nothing about them is deprecated."
