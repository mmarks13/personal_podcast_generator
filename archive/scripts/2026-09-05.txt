## Twenty-one ways to shrink the same model
A: Right, so this is the other end of the telescope entirely. One person, one RTX 5080, sixteen gigabytes.
B: This is the LocalLLaMA post.
A: This is the LocalLLaMA post. He took twenty-one compressed builds of Qwen three point eight twenty-seven B — every one he could find that fits in sixteen gigs — ran them on his own C code, and published a table. A hundred forty-one upvotes, ninety-nine percent of votes positive, which for that subreddit means nobody found a hole in it.
B: What's he measuring? Because "which quant is best" usually means somebody ran a multiple-choice benchmark eight times.
A: He isn't measuring accuracy. He's measuring KL divergence against the uncompressed model, and that's why I wanted to talk about it.
B: Explain it for me the way you'd explain it to a room.
A: The full-precision model, at each position in the text, produces a probability distribution over every possible next token. Not a choice — a distribution. Ten percent here, three percent there, a long tail of almost-nothing. Quantize it, and you get a different distribution at that same position. KL divergence is the number that says how far apart those two distributions are, averaged over all the tokens in the test.
B: So zero means the compressed model is thinking the same thoughts.
A: Zero means it's producing the same distribution. And I like it as a metric precisely because it doesn't let a model hide. A benchmark score can survive real damage — the compressed model gets the same answer through a distribution that's been mangled everywhere it doesn't happen to matter. Divergence sees the mangling.
B: Alright, numbers.
A: Worst in his table: a two-bit quantization-aware build, mean divergence zero point eight nine, eight point two gigs on disk. Best top-token agreement in that neighborhood is eighty-six percent. Move up the table: an IQ2-S build at zero point five one. Then here's the one. A build called Ridge, three point seven bits per weight, eleven point seven gigabytes — divergence zero point four eight. And an IQ3 build, nine point four gigabytes, two and a third gigs smaller — zero point three eight.
B: [surprised] The smaller file is closer to the original.
A: The smaller file is closer to the original. Bits per weight is not fidelity. What matters is where you spend them — which layers keep precision, which tensors get crushed, whether the recipe was calibrated. Two files can advertise the same average and be entirely different objects.
B: That's genuinely useful, and it's the thing everybody gets wrong when they pick a download by file size.
A: His overall pick is a four-bit IQ4-X-S build from bartowski, with a couple of alternates for people who want a less filtered model.
B: Okay. Now let me be the person who has actually done this on a sixteen gig card, because there's a hole in it.
A: Go.
B: The weights are not the whole budget. Your KV cache lives in that same sixteen gigabytes, and it grows with context. So the winning file — the four-bit one — is around eleven, twelve gigs of weights and now you have four left for everything else, which is not very much context.
A: And the post doesn't report the cache settings.
B: The post doesn't report the cache quantization, or how much context he could actually fit, or how many tokens he sampled per model. The top comment asks him all three. And a commenter makes the case that the three-bit build is the real sweet spot, because it leaves room for something like ninety-eight thousand tokens of context at eight-bit cache if you offload the vision tower — and says quantizing the cache to four bits is a bad idea.
A: So the ranking is right and the recommendation might not be.
B: The ranking is right for weights in isolation. The recommendation depends on what you're doing. If you're doing single-turn code completion, take the best divergence. If you're running an agent that needs eighty thousand tokens of context, the third-place file that leaves room for the conversation beats the first-place file that doesn't.
A: I want to note the shape of this, because it's the same shape as our first story in a different key. Somebody wrote down a boundary — sixteen gigabytes — and then everything interesting is in what the boundary was actually holding.
