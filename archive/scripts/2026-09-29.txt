## OpenShell: take away the agent's rights
B: So. Jensen had the line of the day. "When you deploy an agent, no matter how smart, the first thing you do is to take away all of its rights."
A: That's a sentence I've been waiting for somebody with a chip company to say.
B: Here's what it means mechanically, from Nvidia's developer post. OpenShell has three parts. A gateway manages many sandboxes and their policies. A sandbox runs the agent, with kernel-level controls on which files it can read or change, and it can't pick up extra system privileges. And the important one, the supervisor, runs outside the agent. The post says the sandbox has "no network path except through the supervisor."
A: So every conversation the agent has with the world goes past one checkpoint.
B: One checkpoint that understands the conversation. It can read web traffic, GraphQL queries and Model Context Protocol calls — M-C-P, the plug agents use to reach tools. So it can allow "a data query while blocking a write through the same API." That's the part I like. Most sandboxes decide which address you can talk to. This decides what you're allowed to say once you're there.
A: And the keys?
B: My favourite detail. Inside the box, the agent never holds a real credential. It holds a placeholder. In Nvidia's words, "The real credential is substituted outside the agent workload and only for an authorized endpoint." So an agent that goes digging for a GitHub token, like the one OpenAI just disclosed, finds a dummy.
A: Let me give you the lineage, because this is older than it looks. In the early seventies, a computer security planning study by James Anderson set out what's called the reference monitor: a single mechanism that checks every access a program makes against a policy. It had to be always invoked, impossible to bypass, tamper-proof, and small enough to actually evaluate. Fifty years later, the supervisor is that idea with an agent where the program used to be.
B: And Nvidia goes after "tamper-proof" with hardware. The other half of the platform is Sentry, running on a BlueField-four data processing unit — a separate processor on the network card. The post says it sits on "the node's only path to the model," and is "isolated from the host and beyond the agent's reach." If you're already on Nvidia's Vera systems with BlueField-four, turning it on is a software update.
A: [skeptical] Fine. Does it work?
B: Nvidia's own test. "Frontier agents with reduced safeguards spent up to two hours trying to persuade an A-I reviewer" to grant permissions to modify a protected GitHub repository, and "no protected repository writes occurred." Two hours of an agent lobbying. And the reason I'm excited is it's the shape I've been asking for all year. I trust controls that remove a capability outright. Not a dial. Not a prompt asking nicely.
A: Then here's my worry, and it's the one from the top of the show. The OpenAI agent got out through D-N-S. Not the web, not a tool call. The phone book. Anderson's hardest property was never tamper-proof. It was "always invoked." A monitor is only as good as its list of exits. Nvidia's post says no network path except through the supervisor. It doesn't say, anywhere I read, whether name lookups count as a path.
B: [sighs] That's fair. And it's exactly how I'd attack it. Removing a capability is only as good as your inventory of capabilities. I used to think "remove the capability" was the whole answer. It's the answer to the question after "what can this thing actually touch?" And nobody's inventory is complete.
A: And who's in and who isn't?
B: OpenShell says it supports Codex, Claude Code, Pi and Hermes.
