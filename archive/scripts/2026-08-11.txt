## The mark is not the author
A: It has to. Anthropic is deploying two different marking systems under one policy, and neither is an authorship oracle.
B: Begin with why now.
A: Anthropic says it signed the European Union A I Act's Article fifty, paragraph two, Code of Practice on transparency for A I-generated content. For new models launched in the European Union on or after August second, marking is present at launch. Older models get a transition period. Once a supported model marks output, the policy applies wherever Claude is offered, not only inside Europe.
B: So geography triggers the obligation, while the implementation travels with the model.
A: That is Anthropic's description. Text and files then split. For text, the model weaves an imperceptible watermark into the generated language. The watermark is part of the text, so copy and paste carries it, and some editing may leave it detectable.
B: What pattern is being woven? Token choices? Word order? Punctuation?
A: Anthropic does not say. The help page promises more detailed technical guidance and says detection documentation is forthcoming. Until that arrives, we know the claimed behavior and the failure cases, not the encoding method, detector threshold, false-positive rate, or quality tradeoff.
B: Anthropic says the mark does not change meaning, quality, or readability.
A: It says that. The page gives no evaluation supporting the quality claim. A compliance team should separate the product assertion from a measured result.
B: And the mark is applied at the model level. That is why it appears from the A P I, Claude Code, Cowork, Tag, and through Amazon Web Services, Google Cloud, or Microsoft Foundry.
A: Yes. Some platforms may not support every file-marking feature, but supported text marking follows the model surface. That breadth matters to a company with five different ways of reaching Claude. It also creates a subtle authorship trap.
B: I paste a human-written policy into Claude and ask for proofreading.
A: Claude returns revised text carrying a mark. Detection may now say Claude processed it. That does not mean Claude originated the policy, owns the ideas, or wrote every sentence. Anthropic names proofreading, translation, summarization, and file conversion as cases where underlying material came from somewhere else.
B: Then a university cannot treat mark detected as student cheated.
A: Not responsibly. Nor can a publisher treat it as a complete chain of custody. The marked passage may have been excerpted, combined with other material, or edited after Claude touched it.
B: The inverse fails too.
A: Strongly. No detected mark does not mean human-made. Anthropic lists older models, heavy editing, paraphrasing, translation, mixing into other writing, very short passages, unsupported platforms, and file conversion or screenshots that strip metadata. A negative result is not an innocence certificate.
B: That makes the text mark sound less like a verdict and more like a lossy process log.
A: Good description. It can add evidence that a supported Claude model touched enough of this text for its signal to remain. It cannot reconstruct all the hands, models, and edits before or after.
B: Files get the other system.
A: Supported S V G, P N G, and J P G outputs receive signed provenance metadata following the C two P A open standard, the Coalition for Content Provenance and Authenticity. B: Change the bound file and its cryptographic hash no longer matches.
A: Right. Alter the provenance data without authorization and the signature check fails. That gives tamper evidence and a way to evaluate who or what signed the claim.
B: It does not make the image true.
A: No. A valid signature can tell you that a named system asserted a processing event and that the bound asset has not changed in an undetected way since. It cannot tell you that the pictured event happened, that every assertion is honest, or that the person publishing it owns the source material.
B: And metadata can be removed.
A: The C two P A security specification is blunt about that. Hashes and signatures expose tampering with a manifest or bound asset, but the standard does not prevent complete removal of the manifest. ## Five walls and a live project
B: Docker describes five isolation layers: hypervisor, network, Docker engine, workspace, and credential proxy. The important word is layers. A micro virtual machine can protect the host operating system while a read-write mount still gives the agent authority over the project you care about.
A: Take the micro virtual machine first.
B: Each sandbox has its own Linux kernel. Processes inside are separate from the host and other sandboxes. The agent can have sudo privileges inside that machine because the hypervisor, not a polite in-machine user account, is the primary boundary.
A: Which is materially different from putting an agent in an ordinary container that shares the host kernel.
B: Yes. Packages, services, and the agent's containers live inside the micro virtual machine. Docker also gives the sandbox its own Docker engine, so a coding agent can build images or run Compose without receiving the host Docker socket.
A: Mounting the host socket would let the supposedly contained agent control the host daemon and everything that daemon can reach.
B: Docker avoids that path for processes inside the sandbox. But the documentation names an exception: local standard-input M C P servers run on the host. If one of those tools starts a host process or a host container, the micro virtual machine is no longer the relevant boundary for that action.
A: A sandboxed agent can hold an unsandboxed tool handle.
B: Precisely. The tool's implementation and policy decide what that handle can do.
A: Network layer.
B: Each sandbox gets an isolated network. Web traffic goes through a host proxy that enforces domain policy. Docker says raw T C P, U D P, and I C M P are blocked, along with private and link-local address ranges. The setup offers three presets. Open allows everything. Balanced denies by default while allowing common development sites. Locked Down blocks everything until you add a rule.
A: Balanced sounds safe until common becomes a wildcard broad enough to contain a service you did not intend.
B: Docker makes that warning itself. Some default domains are broad. The practical action is to list the active rules, remove what the job does not need, and watch the outbound connection log. A default-deny label is a starting configuration, not evidence that the allow list is minimal.
A: Credentials cross that proxy too.
B: For supported services, the real secret stays on the host. The sandbox sees a sentinel value. When an allowed request matches the declared service, the host proxy inserts the actual authentication header on the way out.
A: That prevents the agent from printing the raw key. It does not prevent the agent from spending the key's authority through an allowed request.
B: Exactly. Secret confidentiality and service authorization are different. A model token can remain unreadable while the agent still calls the model. A GitHub token can remain unreadable while an allowed tool uses it to open a pull request. Scope the account and service permissions as though the agent can exercise them, because it can.
A: Then comes the workspace, where the product's reassuring name meets the user's files.
B: Direct mode is the default. Docker mounts the selected working tree read-write, and changes appear on the host immediately. The documentation says there is no isolation between the agent and that workspace in direct mode.
A: Not merely source files.
B: Correct. The agent can alter build scripts, continuous-integration configuration, editor tasks, project-level A I instructions, hidden executables, and Git hooks. Docker points out that Git-hook changes do not appear in an ordinary Git diff. Deleting the micro virtual machine does not reverse edits already written into the host working tree.
A: That is the sentence I want people to retain. Disposable environment does not mean reversible project.
B: Clone mode changes that. The host repository enters read-only, while the agent works on a private clone inside the micro virtual machine. Changes stay there until you deliberately fetch them or the agent pushes them somewhere its network and credentials permit.
A: And deleting the sandbox deletes that private clone, so isolation adds a recovery obligation in the other direction.
B: Fetch or push work you want to keep before removal. A good boundary can protect you from unwanted writes and still eat wanted writes if you forget where they live.
A: You have named four layers. What makes the fifth more than credential injection?
B: Docker treats credentials as their own isolation layer because the sandbox can use services without possessing raw secrets. But I would add two narrow crossings that are easy to overlook. Shared agent skills can be mounted read-write from one host-side store into multiple sandboxes. One sandbox can change instructions another later consumes. And the M C P gateway brokers tools that may run outside the virtual machine.
A: So two sandboxes that share skills are not independent at the instruction layer, even if their kernels cannot talk.
B: Right. Docker calls that a trust-boundary exception. You can opt out of shared skills for a sensitive run. You should also inventory every M C P server and ask where it executes, not merely whether the calling agent is sandboxed.
A: Give me your launch checklist without turning this into a configuration manual.
B: For an untrusted coding task: use clone mode. Start with Locked Down networking and add only the model provider, package registries, and repository host the task requires. Use a narrowly scoped account. Opt out of shared skills unless you need them. Permit no host-side tool you have not reviewed. Preserve the commits before deletion. Then inspect both the Git changes and the network log.
A: Docker says the command-line sandbox is free, including commercial use. Centralized organization governance is the paid part.
B: Which matters because a local policy chosen by one careful developer is not an organizational control. A company needs the same network, filesystem, credential, and M C P rules applied across every machine, plus evidence that they stayed applied.
A: Does this make unattended agent execution safe?
B: It makes one answer much better. The agent should not own the host merely because it needed to run a build. It does not make the shared repository harmless, the allowed destinations trustworthy, the tool servers contained, or the service permissions appropriate.
A: Then Docker has built a real security product, and the honest product description is longer than sandbox.
B: Much longer. My test is simple: name the asset you are protecting. Host operating system? Working tree? credentials? remote account? downstream deployment? Then point to the layer that protects that asset and the path that still crosses it.
