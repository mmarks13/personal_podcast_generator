## Thirty billion on the desk
B: Start with the uncomfortable version. Thirty billion parameters at full precision would require more than fifty-five gigabytes just for the model. That is before the temporary state needed to generate a response, before images, and before the rest of an agent runtime.
A: So Meta did not make thirty billion small. It changed the representation and the traffic pattern.
B: Exactly. Meta says its roughly four-bit quantized language model comes in under twenty gigabytes. The release is designed so that build can share a twenty-four- or thirty-two-gigabyte memory envelope with the key-value cache, the visual encoder, and the speculative drafter.
A: Twenty-four gigabytes is a high-end consumer graphics card, not the average laptop on a kitchen table.
B: Agreed. Meta says Mac or P C with one consumer graphics processor. I would translate that to a well-equipped local machine, often with unified memory or a top-tier card. This is local availability, not universal availability.
A: What occupies the thirty billion?
B: Hugging Face's day-zero implementation describes a dense model with a twenty-eight-billion-parameter text decoder and a two-billion-parameter vision encoder. The visual side handles images and sampled video frames. The text side handles reasoning, code, tool calls, and the language around whatever the encoder saw.
A: Dense means all of that text decoder participates for each token, unlike a mixture-of-experts model that activates only part of a much larger weight set.
B: Right, which makes memory movement an immediate concern. The text decoder alternates three sliding-window attention layers with one full-attention layer. Most layers look within a bounded neighborhood. Every fourth layer can connect across the broader context.
A: Local streets, then an arterial road.
B: With the usual warning that information can still be compressed or lost as it travels. The point is computational: do not pay full global attention in every layer when periodic global mixing may preserve enough reach.
A: And the key-value cache?
B: The implementation shares each key-value head across sixteen query heads. During generation, that cache holds the attention state from earlier tokens. Sharing means the model stores fewer distinct keys and values, and Hugging Face says it reduces that cache memory by a factor of sixteen relative to giving every query head its own pair.
A: Which matters more as the conversation and tool trace get longer. A model may fit at startup and still run out of memory halfway through an agent job because its working state keeps growing.
B: Precisely. Local deployment has at least two budgets: weights that remain resident, and state that grows with context. Meta's envelope claim is valuable because it acknowledges both, though a builder still needs to test the actual context, images, and concurrency they intend to run.
A: The separate drafter is the more unusual item in the box.
B: We have walked through speculative decoding before. A smaller model proposes future tokens; the main model checks them and accepts only proposals consistent with what it would have generated. Muse Glimmer bundles a lightweight companion based on D Flash, which proposes a block rather than waiting for the large model to author every next token serially.
A: The companion can be wrong cheaply.
B: Yes. The expensive model verifies proposed tokens in parallel, keeps the accepted prefix, and corrects the rest. Meta says the result is significantly faster generation without sacrificing output quality. The trade is extra memory for the drafter, which is why the quantized envelope has to make room for it.
A: This is a nice release detail. Speculative decoding is often described as a serving optimization somebody else will add later. Here the drafter is part of the model package and supported on day one by both Transformers and llama dot C P P.
B: That changes the first-run experience. The release also has support across V L L M and other common runtimes. A local model matters more when using it does not require a month of custom kernel work.
A: How did Meta teach a model this size to behave like an agent rather than a generic chatbot?
B: Meta describes three stages. During pre-training, it used Muse Spark outputs and logit distillation, transferring more than just the teacher's final answer. Mid-training shifted toward longer contexts, agent-heavy data, and richer reasoning traces. Post-training mixed supervised fine-tuning, on-policy distillation, and reinforcement learning across coding, reasoning, general, and agentic work.
A: Distillation is doing two jobs in today's episode. Here it transfers behavior from a larger teacher into a model that can live locally. In the Multiverse systems note, the question is how to make that transfer cheap enough to repeat.
B: And Meta's target is unusually coherent. A local personal agent needs tool use, recovery after a failed call, long context, and perception of screenshots or documents. Those capabilities are more relevant to the product than winning every general knowledge test.
A: It does not win every agent test either.
B: No. Hugging Face reproduces Meta's published comparison against Gemma four and Qwen three point six models of similar size. On S W E Bench Pro, Muse Glimmer scores fifty-one point two to Qwen's fifty point two. On S W E Bench Verified, Muse scores seventy-six while Qwen scores seventy-seven point two. On O S World Verified, Muse is further behind: sixty-five point nine to seventy-five point six.

## The test that raises its own bar
A: A good terminal task is a small contract among four things. The public instruction says what to achieve. The initialized workspace contains the evidence and obstacles. A reference solution proves there is at least one path through. A private verifier decides whether the final state actually satisfies the request.
B: Change one without the others and you get a broken lesson.
A: Exactly. Make the verifier stricter without updating the instruction, and the agent is punished for a secret requirement. Lengthen the instruction without changing the environment, and the requested task may be impossible. Generate a plausible solution without running it, and the supposed training example may teach an error.
B: Recursive Synthetic Terminal Tasks begins from the solution rather than from a clever new prompt.
A: That is the key move. The system selects one of forty rewrite operators suited to the seed task. It writes a transformation contract, extends the executable solution, modifies the environment if necessary, then realigns the verifier and public instruction around the new workflow.
B: Give me a rewrite that is more than add three extra steps.
A: The paper follows one family of JSON-difference tasks. The seed asks for six reports from fixed fixture pairs, and its reference solution is ten non-empty shell lines. A later generation moves the comparison matrix into a configuration file. Another corrupts that configuration so the agent must diagnose and repair it. Another uses a change log to introduce a new nested-fixture case. By round fifteen, the agent has to reconcile inconsistent configuration, fixtures, expected counts, generated reports, and tests. The reference solution has grown to three hundred forty-seven lines.
B: That is harder. It is also at risk of becoming bureaucracy generated from bureaucracy.
A: Hold that objection. First, the validation. The reference solution runs inside a fresh sandbox, and the private verifier checks the resulting workspace. The paper calls a passing reference solution oracle validity: proof that the task can be completed from the stated initial condition.
B: Proof that one scripted path can complete it.
A: Correct. Not proof that the task is natural, useful, or fairly phrased. So the pipeline adds contract validity. Every condition that can change the reward must either appear in the public instruction or be discoverable from ordinary workspace evidence such as documentation, configuration, fixtures, logs, or command output.
B: And the model being evaluated cannot open the answer key or private tests.
A: The harness withholds both. The verifier also looks for empty, stale, hard-coded, or verifier-specific shortcuts. Static filters catch missing files, leaked private details, near-duplicates, and malformed environments before the more expensive sandbox run. A bounded repair loop can fix recoverable construction failures; persistent failures are discarded.
B: Then accepted tasks become seeds for another rewrite.
A: Yes, with caps on parent lineage, domain, rewrite family, and generation cohort so one fertile ancestor does not consume the population. Starting from six hundred thirty-nine verified bootstrap tasks, the authors report fifteen generations and thirty-seven thousand four hundred eighty-four accepted tasks, at roughly five cents apiece.
B: Five cents is the synthesis cost the authors report, not the full cost of inventing the framework, curating the original pool, training a model, or auditing what came out.
A: Important distinction. The loop has no human author writing each child, but humans designed the operators, validity rules, harness, seed policy, and experiments. Automation changes the marginal task cost. It does not erase system-design cost.
B: How do they know later generations are genuinely harder instead of merely longer?
A: They hold the solver fixed and watch performance fall. From round one to round fifteen, the median reference solution grows from sixty-seven to three hundred seventy-four lines, and the median number of executed commands grows from forty to two hundred forty-four. Over the same span, DeepSeek V four Pro's pass-at-four rate falls from ninety percent to two point five percent.
B: That is evidence of difficulty for that solver. It does not tell me the new difficulty resembles the failures my coding agent meets at work.
A: Agreed. The paper does more than count lines: partial verifier credit declines too, and the authors audit domain and rewrite diversity. They also report transfer after training on the synthetic pool. Supervised fine-tuning on successful Qwen three point five trajectories improves two model sizes by as much as ten points across Terminal Bench two, Terminal Bench Hard, and Long-Horizon Terminal Bench.
B: Terminal Bench Hard was constructed independently of this synthesis pool, which helps.
A: It helps. It is still an evaluation inside the terminal-agent family. A distribution of package files, build tools, configuration, and shell state is broader than one repository and narrower than all useful software work.
B: And the headline reinforcement-learning result needs a correction before anyone builds a slide around it.
A: It does. The current preprint contradicts itself. Its abstract and main results table put the trained twenty-seven-billion-parameter model at forty-nine point four four on Terminal Bench two, a twenty-percent relative gain over the base. The conclusion says forty-six point oh seven and eleven point eight two percent. Both cannot describe the same reported run.
B: That is unusually easy to catch in a paper about verifiers.
A: [dryly] The reader supplied the cross-file consistency check. We can safely report the supervised-training result because that claim is consistent in the abstract and results. We should not choose between the conflicting reinforcement-learning numbers until the authors correct the record.
B: Does the mismatch change your view of the task factory?
A: It lowers confidence in the polish of the current preprint. It does not erase the executable artifact, the synthesis method, or the direction of the experiments. But exact performance claims are load-bearing. A corrected version should state which row is authoritative and why the other numbers appeared.
B: My larger worry is self-reinforcing artificiality. The generator makes tasks that its verifier can grade. The policy learns the regularities of those tasks. The next evaluation rewards the same kind of state change. You can build a beautifully measured loop around a narrow idea of work.
A: Yes. Oracle validity answers can this task be solved. Contract validity answers was the deal stated fairly. Neither answers would a real user ask for this, or does solving it improve behavior outside the factory.
B: The paper's concrete lineage makes the problem visible. Repairing inconsistent configuration and reconciling reports is plausible work. Repeating that pattern through fifteen generations might select for patience with generated paperwork rather than judgment about a live codebase.
A: The authors try to resist collapse with forty operators, domain caps, lineage caps, novelty checks, and held-out benchmarks. Their conclusion still notes a high-similarity tail that needs more targeted deduplication as the pool grows.
B: So if I borrowed this for a company, I would not start from public benchmark tasks. I would start from a small set of real, permission-cleared failures from our own build and deployment systems.
A: Then preserve a held-out set of untouched real incidents. The generated descendants can train the agent. They should not be the only exam used to declare the agent improved.
B: I would also inspect samples from every generation. Not to hand-author them, but to ask whether the task still has a believable user, whether the required evidence is findable, and whether the verifier rewards outcome rather than one favored implementation.
A: And track family-level gains. If performance improves only on descendants of one seed or one rewrite operator, the overall average can hide memorization of a task dialect.
B: Would you use the reported five-cent tasks for reinforcement learning today?
A: As one training pool, after reproducing the validators and correcting the paper's numerical conflict. I would not use them as the sole source of reward, and I would not interpret a longer generated solution as business value.
B: I would go slightly faster. The executable proof and discoverability check are stronger than the synthetic instructions most teams already use. I would feed a sample to a model, then watch where human reviewers call the task contrived.
A: That is a real experiment. The paper has made generation cheap enough that curation, not scarcity, becomes the next bottleneck.
B: I am not sure it made curation cheaper.
A: Neither am I. It made the pile arrive faster.
